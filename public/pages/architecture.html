🚀 部署架构：CQRS 读写分离 (初学者笔记)

这份笔记带你彻底看懂 RomanceSpace 的底层生命线。我们是如何用一台不到百元的 2h2g 小霸王服务器，撬动万级高并发访问的？全靠一种叫做“CQRS（读写分离）”的魔法。

💡 一句话总结我们到底在干嘛：
写操作（造页面，贼费 CPU）：统统丢给 VPS 老黄牛去干。
读操作（看页面，并发极高）：全让 Cloudflare CDN 和 Worker 去免费分发。

一、为什么我们需要这套架构？ (分析)

想象一下传统的做站方式：用户要看 `xiaoming` 这个网页，VPS 里的 PHP/Node.js 就要去数据库里搜小明的资料，然后把资料拼凑进 HTML 里，再吐给用户。

  • 传统痛点：如果有一千个人同时看，这台机器瞬间就会被数据库连接数和 CPU 运算撑爆炸。
  • 我们的解法：我们把 页面拼接 这一步“左移”了。在这 1000 个人来看之前，当小明点击“保存”的那一瞬间，我们的 VPS 就已经把 HTML 拼好，并且静态地扔进了 Cloudflare R2 云仓库。等这 1000 个人来的时候，流量根本碰不到 VPS！

二、三大金刚：基础设施图鉴 (说明)

1
Cloudflare KV：毫秒级路由簿
这是什么？ 这是一个极速的全球分布式键值对数据库。
存些啥？ 记着谁的页面可以看，谁被封号了。比如 `{"xiaoming": {"status": 1}}`。
如何协作？ Worker 接到访客请求的第一步就是查它（不到 10 毫秒）。一旦发现 status 是 0 甚至查无此人，直接 404，绝不浪费 R2 的读取。
2
Cloudflare R2：无底洞静态仓库
这是什么？ 兼容 S3 的对象存储器。
存些啥？ 我们把做好的成品网页（比如 pages/xiaoming/index.html）和大量的模板图片等放这。
如何协作？ VPS 做完苦力把网页扔进去，Worker 从这里拿网页展示给亿万网友。
3
Supabase / PostgreSQL：真正的账本
这是什么？ 完全关系型的核心大本营。
存些啥？ 用户付了多少钱，原始填写的表单究竟是什么字。
如何协作？ 前端（用户看到的操作面板）和 Worker 绝不允许连接它！ 所有的读写只能由后端 VPS (`api.885201314.xyz`) 安全代理进行。

三、全盘运作流程 (怎样实现的)

当用户在我们的平台走完从创建到分发的整个生命周期时，系统是这么跑的：

阶段 主角 发生了什么魔法？
1. 收集情报 Frontend (React Builder) 你在浏览器里欢快地输入信息，拖拽图片。此时全都在浏览器本地算（BSR），一毛钱不花我们服务器的。
2. 开始制衣 Backend (VPS Node.js) 你满意了，点击了“提交”。请求被送到 `api.885201314.xyz/api/project/render`。VPS 接到数据后核对防刷、计费。然后调用强权把你的数据灌入模板里，合成一个最终版的静态网页并推送到 R2，同时在 KV 里登记。
3. 全球展示 Worker (Cloudflare CDN) 你把你做好的网址 `test.885201314.xyz` 发到各大社交平台。几万吃瓜群众同时点击。流量瞬间撞在 Cloudflare 边缘节点上。Worker 一看 KV 有这个人，直接从 R2（甚至从边缘内存缓存里）拿出那个 HTML 给网民，VPS 这个时候甚至在打呼噜。
⚠️ 注意防坑：API 独立通道
所有的后台接口都在 api.885201314.xyz 域名下。这个域名被我们在 DNS 里强制配成了 Proxied 并且绕过了 Worker Router 的大通配符 *.885201314.xyz，这样用户发来的登录请求、保存请求才能畅通无阻地直接找到 VPS 服务器。
