🌐 Worker 边缘网关 (高速分发者) 开发手册

💡 重要的系统常识提醒：
打开任一生成的专属网站链接，本质就是您的浏览器发出的请求打到了 Worker 这个大管家上。在五大仓库中，RomanceSpace-Worker 是一个只读的高速入口，一旦您打开网址，等效于请求直接开始接受 Worker 的处理！

为了保障毫秒级别的相应速度，它不参与任何内容的渲染，它的配置由其目录下的 wrangler.toml 进行授权。通过 kv_namespaces 绑定验证簿，通过 r2_buckets 绑定大货仓。

一、核心源码流程（分发器运行解析）

步骤 1：主域名分化与拦截
举例：当流量为 romance.com 根域名时，执行纯净跳转重定向至 www.885201314.xyz （主平台）。一旦为带有三级标识的（如：xiaoming.romance.com），就进入极速检查阶段。 
// 根域名识别判定代码块样例
const url = new URL(request.url);
const hostname = url.hostname;

if (isMainDomain(hostname)) {
    return Response.redirect(`https://www.885201314.xyz${url.pathname}`, 301);
}
return handleSubdomainRequest(request, subdomain, env, ctx);

二、三级大坝（抗住 100% 极速并发展示）

🧱 第 1 级缓存：Cache API (橱窗展示门面)
每次拿到结果后，都会通过 const cache = caches.default 进行一次存储。如果是热门网站（如已经被人打开了），Worker 刚刚一接手便直接原路以 0ms 返回网页，根本不往下运行任何代码。
🧱 第 2 级鉴权：KV Lookup (小本子挂号)
只有当第1级由于初次访问没命中时，它才会通过调用向 Cloudflare 绑定的高速 KV 发起询价：要求给出是否有这个人存在的数据字典。
const projectConfigStr = await env.ROMANCESPACE_KV.get(subdomain);
🧱 第 3 级提货：R2 Bucket (永久冷库读取)
确认确实开通过这个站点，Worker 使用自身被授予的权限到 R2 请求后端早早放进来的 HTML 死静态文件块（await env.RS_BUCKET.get(...)）。取出并向第1级的展示面板填充副本。返回浏览器！
