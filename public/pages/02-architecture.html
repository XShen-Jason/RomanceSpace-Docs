Chapter 2

宏观架构：上帝视角下的协调

RomanceSpace 并非一个臃肿的单体应用。我们通过 CQRS (Command Query Responsibility Segregation) 读写分离架构，将系统拆分为多个协作单元。

1. 核心架构：读写垂直切分

我们遵循的一条铁律是：“让 VPS 后端承担写操作（渲染、校验），让 Cloudflare 边缘承担读操作（访问分发）。”

操作类型 承载主力 技术栈 优势
写 (Commands) 中央 VPS (云服务器) Node.js / Nginx 逻辑可控、高性能渲染、安全。
读 (Queries) Cloudflare Worker / CDN V8 Isolates / Edge 全球 0 延迟、无需冷启动、极高并发。

2. 六大仓库协作体系

项目被拆分为物理隔离的六个仓库，每个仓库各司其职：

1
Frontend (SPA - Cloudflare Pages) 完全静态化的 React 应用。职责：负责 Builder 编辑器界面、BSR 预览引擎、Gallery 展示。它不持有任何 DB/R2 密钥，纯通过 AJAX 与后端通信。
2
Backend (API Central - VPS) 整个系统的“中央枢纽”。职责：唯一持有 R2/KV/DB 写入特权的单元。执行 HTML 注入渲染、域名重复性校验、CDN 缓存清除（Purge）。
3
Worker (Edge Gateway - Cloudflare) 拦截 *.885201314.xyz。职责：正则校验子域名非法性、查 KV 路由、从 R2 抓取 HTML、注入安全响应头。
4
Templates (Static Assets - R2) 纯 HTML/CSS 片段库。由 CI 自动同步至 R2 的 /templates/ 目录，确保持久存储与版本隔离。
5
Infrastructure (DB/KV/R2) 数据层。Supabase 负责权限与事务；R2 负责海量 HTML 文件；KV 负责全网毫秒级路由查找。
6
Docs (知识库) 就是你现在看到的这套手册，负责记录项目的所有技术细节。
⚠️ 安全红线：
Frontend 和 Worker 严禁直接连接 Supabase 数据库！所有敏感数据的读取与修改必须通过 Backend VPS 代理进行，以防泄露机密密钥。
