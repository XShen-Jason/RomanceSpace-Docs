🌐 Worker 边缘网关原理 (初学者笔记)

做为五大仓库的守门员，RomanceSpace-Worker 是一个部署在 Cloudflare 全球几十万个节点上的无服务器函数 (Serverless Function)。你要记住的唯一偶像是：“天下武功，唯快不破！”

💡 这是个什么角色？ (分析)
每次有人在手机上打开 `xiaoming.885201314.xyz`，请求不会飘洋过海飞到我们的 VPS 里，而是瞬间被离用户最近的 Cloudflare 节点（比如上海、东京、硅谷）拦截。Worker 就是跑在这个节点上的“小保安”。它唯一的职责就是：**光速找网页，然后甩给用户。**

一、 核心分发四大绝招 (流程解析)

当几万个吃瓜群众同时涌入一个小网页时，Worker 凭借以下四道防线，硬扛下所有流量：

1
超级大坝：判断 URL (主路由分化)
动作：一看访问的是主域名 885201314.xyz，直接踢走，301 重定向到 www.885201314.xyz（前端主站）。
一看访问的是静态资源 /assets/*，直接给它加上 7 天不死缓存，让浏览器自己去吞。
一看是个子域名 xiaoming，进入下一道防线。
🧱 第 1 级拦截：Cache API (橱窗展示)
如果之前有人看过“小明”的网页，Worker 内存橱窗里已经缓存了一份。只要没过期（1小时内），Worker 立刻以 0ms 甩出这份拷贝，这叫“边缘命中 (Edge Hit)”，完全不烧任何数据库额度。
🧱 第 2 级鉴权：KV Lookup (翻小本子)
如果橱窗里没有，Worker 会掏出随身带的 KV 小本子查一下：“小明在不在咱们系统里？”如果查无此人，或者账号被封，直接送客 (404 / 403)。如果在，那就知道了小明用的是什么模板。
🧱 第 3 级提货：R2 Bucket (进冷库拿货)
小本子上说小明是 VIP，且用的是经典模板。Worker 就会拿着仓库钥匙去 R2 硬盘里，精准找出 pages/xiaoming/index.html 这个文件，取出来，并在橱窗 (Cache) 里放一份备份，最后拿给访客看。

二、 动态“引流”补刀技术 (商业应用)

4
动态修改与注入广告
动作：虽然存在 R2 里的 HTML 是纯静态的死文本，但 Worker 在提取出来交给用户之前，有一段神奇的过滤代码 (`HTMLRewriter`)。
效果：它会在所有网页的底部，偷偷追加一行按钮：“我也要免费制作同款网页 🚀”。
牛逼在哪？以后就算你要换这句广告词，或者换主站链接，你根本不用修改 R2 里的几万个网页，只要在 Worker 里改一行代码，几秒钟内全球几十万个网页全换上新广告词！

三、 这套架构的“降维打击”在哪 (总结)

⚠️ 零服务器压力：
由于 Worker 拦截了 100% 的查看请求，而且把静态资源缓存做到了极致。你的 VPS 从头到尾连个响声都没听见。这也就是为什么，即便全网千万级曝光，你那台可怜的 2h2g 小服务器也绝不会崩溃，因为它压根没有参与这场流量狂欢。这就是 SaaS 级边缘计算架构的恐怖之处。
