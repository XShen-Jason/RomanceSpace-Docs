🔗 子域名分配与数据绑定流程 (基于 CQRS 架构)

这个体系最魔法的地方在于：只要主平台发一纸“调令”（调一条 API），属于用户专属的小网页就立刻在几秒内诞生，并分配好了独一无二的子网址（如 xiaoming.885201314.xyz）。

在最新版的读写分离架构下，下面说明这条链路是怎么走通的。

一、基础原理：Cloudflare DNS 泛解析

为了做到让每个用户都能自由命名网址，而不需要管理员去后台一条一条添加 DNS 记录，我们在域名管理处设置了 泛解析（Wildcard DNS）。

配置内容： *.885201314.xyz -> 指向 RomanceSpace-Worker 网关

  • 也就是说，无论是 apple.885201314.xyz 还是 banana.885201314.xyz，DNS 解析后都会被瞬间转发到我们的 Worker 门前。
  • 到了门前后，Worker 会掐头去尾，提取出最前面的那个词（比如 apple 或 banana）。
  • Worker 拿着这个词，去超高速的 KV 库（指示牌）里翻找：这个词被开通绑过了吗？

二、业务运转全流程：从填表到网页诞生

下面展示了一个完整的“开通”链路。这是主站服务器、内部 VPS 后端（重度计算）、和 Cloudflare Worker（轻量分发）协作的过程。

1

用户在您的“主站”大厅游览

小明在您的主站页面上逛，看中了一个纪念日模板（代号：anniversary）。

2

用户填写定制信息

小明选定后，主站网页弹出一个表单，让小明输入：男方名字、女方名字、想说的话、想要的前缀拼音。小明填入了 xiaoming。

3

主站查重与扣费

主网站的服务器接收到了提交。由于 xiaoming 这个词全站唯一，主服务器查了下数据库，发现没人用过，于是允许创建（也许还收了小明 9.9 元），并将该词锁定。

4

主站向“内部 VPS”下达渲染指令

主服务器整理好小明填的数据，往内部专属的 VPS API（POST /api/project/render）发请求。

POST https://api.885201314.xyz/api/project/render
Header: X-Admin-Key="你的安全密钥"
Body: {
  "subdomain": "xiaoming",
  "type": "anniversary",
  "data": { "names": ["小明", "真真"], "message": "一生一世" }
}
5

内部 VPS 执行计算与存储写盘

VPS 后端程序拿到请求后疯狂运转：
1. 像印刷机一样，把“小明”等数据，狠狠注入当场实时编译出的静态 index.html 里。
2. 存进 Supabase 数据库底层存根。
3. 把这份生成的页面传进 CF R2 大仓库的 /pages/xiaoming.html 下，并写一条 KV 记录 xiaoming -> /pages/xiaoming.html。
4. 清洗小明之前的 CDN 缓存。

6

访问生效：光速下发

VPS 给主站返回 {"success": true} 后，小明点开 https://xiaoming.885201314.xyz。
此时负责接客的 Cloudflare Worker 收到网址，秒查 KV 发现该路由存在，于是顺手从 R2 仓库把刚做好的那页 HTML 捞出来展示给小明。
这套流程剥离了 Worker 的计算压力，使其彻底退化纯高速缓存网关，支撑千万级“吃瓜”流量绝不崩溃！

三、关于数据修改与更新

如果小明第二天决定改掉那句“一生一世”怎么办？

完全不用担心。主站只需要重做一遍上面的步骤 4（把新数据再次 POST 给内部 VPS），VPS 就会重新渲染一张带有新文字的网页直接强行覆盖 R2，接着调用 Cloudflare 的紫皮 API 一脚踢飞全世界 CDN 节点上小明那个域名的历史 Cache副本。

小明刷新网址，新文字立马出现。
