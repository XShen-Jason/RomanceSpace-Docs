👑 核心架构演进：满分 SaaS 级重构笔记

这份笔记记录了 RomanceSpace 从早期单点渲染，跨越到“生产级 SaaS 架构”的核心过程。无论你是刚接手项目的新人，还是想要摸清底层逻辑的开发伙伴，这篇大白话笔记都能帮你快速理清思路。

💡 我们的核心口号：Edge First + Static Generation + Browser Builder
简而言之：“用户访问绝不碰 VPS，编辑器全靠浏览器算，黑名单做到零额度消耗！”

一、为什么我们要改架构？（痛点在哪）

早期的 RomanceSpace 就像一个传统饭店：客人（用户）一来，厨师（VPS 服务端）就要现炒现卖（动态拼接 HTML）。这导致了三个问题：

  • VPS 压力大：人一多，2h2g 的小机器根本扛不住。
  • 预览卡顿：用户在网页上改了一句话，不仅 VPS 要算一次，网页的 CSS 还经常因为路径不对而加载失败。
  • 费用风险：Cloudflare R2 和 KV 的读取额度，随时可能因为接口乱调而超标。

二、四大“天王级”技术改造（已实装）

为了解决上述痛点，我们彻底重写了整个架构底座，分为以下四个维度的超级优化：

1
优化一：R2 存储“目录化” & 漂亮 URL
以前我们是怎么存的？ 把网页存成 pages/anna.html，用户访问 anna.885201314.xyz/anna.html，很丑且无法归档图片。
现在怎么存？ 我们统一改为了 pages/anna/index.html。
好处：实现了伪静态的整洁 URL anna.885201314.xyz/，并且以后如果 anna 想传自己的个人照片，可以直接存进这个专属目录里！
*注：Worker 路由里依然保留了老代码的 Fallback，以前生成的 .html 老页面依然保证能打开，不会断联。
2
优化二：Browser-Side Rendering (BSR) 毫秒级防爆预览
什么是 BSR？ 把渲染的活儿全部交给用户的浏览器（前端 React）来做。
现在，当前端 Builder 打开一个模板时，它会偷偷调用 /api/template/raw/anniversary 去拿一次纯净版 HTML（这个接口还在 VPS 端加了 Cache-Control: 3600，防刷爆 R2）。
然后用户打字时，前端用 JS 在本地进行字符串替换，把结果塞进页面里的一个 iframe。不管用户鼠标怎么点，1 个字节都不会发往后端，彻底 0 延迟！
魔法细节 <base> 标签：为了让 CSS 和图片不丢失，我们在塞进 iframe 之前，会动态给 HTML 的头部注入一句 <base href="https://romancespace.885201314.xyz/assets/anniversary/">，完美解决所有相对路径失效的灵异事件。
3
优化三：边缘资产的“变态级强缓存”
我们的 Worker 在拦截 /assets/* 流量时，不再只是单纯转发，而是加上了高达 7天（max-age=604800）的强缓存头。
好处：全球 CDN 节点帮你扛走了 99.9% 的 CSS、JS 和图片流量，连 R2 都收不到请求，真·不讲武德的省钱法。
那用户怎么看最新版页面？ 在最终保存提交后，按钮会自动跳转到带有时间戳的特殊地址：anna.885201314.xyz/?preview=1710000000000，时间戳能暴力击穿一切旧缓存，立竿见影。
4
优化四：DNS 安全与无感“零额度”黑名单
我们想防住哪个调皮的用户注册 api.885201314.xyz 把主干道给占了。所以我们在 Cloudflare KV 设了一个 __sys__blocklist 字典。
如果用户每次创建都要去读 KV，每天 10 万次的免费读取不是很快就烧光了吗？
我们的神仙设计：动态内存缓存！
VPS 在启动的一瞬间，只读 1 次 KV，然后把它永久存在 Node.js 的变量（内存）里。接下来有 100 万个用户点击创建，服务端永远只看内存，0 次 KV 网络请求！
那管理员怎么加黑名单新词？
管理员去 CF 界面改完 KV 后，只需要调一下我们预留的 POST /api/project/config/refresh-blocklist 这个隐藏接口，VPS 就会去老老实实再拉一遍数据并重新锁死在内存里。

三、全景流量分析 (小白秒懂版)

场景 走的方向 (流量从哪过) VPS 的 CPU 在干嘛？ R2 有额度消耗吗？
普通访客看网页 用户 ➔ Cloudflare Edge ➔ R2 (命中缓存直接返回) 0%（完全不知道有人访问） 极少（只有第一次读取消耗）
用户进入编辑器打字 用户的 Chrome 浏览器狂奔 0%（岁月静好） 无
用户点击“更新保存” 用户 ➔ VPS ➔ API 写库 ➔ R2 更新 微量（就核对一下权限写个文件便下班） 1次 Class A 写入操作
⚠️ 开发者红线记录： 如果你要在 `docs` 之外再加一个独立部署的网页应用（比如挂在 Cloudflare Pages 上的 `admin.885201314.xyz`），第一件事必须是把 admin 加入到 KV 黑名单并执行 Refresh 接口！因为 Cloudflare Pages 的路由拦截优先级极高，如果不加黑名单被用户注册到了，系统数据库和实际渲染效果就会出现严重分裂。

四、总结

在这个这套架构下：

  • VPS (服务器)：退居幕后，只负责接收你确认无误的最后一次“写入”盖章。
  • Worker (旁路由)：化身最强前台，用变态级的缓存拦截所有白嫖流量。
  • Browser (浏览器)：承担了所有繁重的实时渲染工作。

RomanceSpace 由此真正毕业，成为一个成本趋近于零、支撑万级真实用户的轻量化浪漫平台。
