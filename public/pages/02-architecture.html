Chapter 2

宏观架构：上帝视角下的协调

RomanceSpace 并非一个臃肿的单体应用。我们通过 CQRS (Command Query Responsibility Segregation) 读写分离架构，将系统拆分为多个协作单元。

1. 核心架构：读写垂直切分

我们遵循的一条铁律是：“让 VPS 后端承担写操作（渲染、校验），让 Cloudflare 边缘承担读操作（访问分发）。”

操作类型 承载主力 技术栈 优势
写 (Commands) 中央 VPS (云服务器) Node.js / Nginx 逻辑可控、高性能渲染、安全。
读 (Queries) Cloudflare Worker / CDN V8 Isolates / Edge 全球 0 延迟、无需冷启动、极高并发。

2. 六大仓库协作体系

项目被拆分为物理隔离的六个仓库，每个仓库各司其职：

1
Frontend (平台前台) React 驱动的 SPA 应用（Cloudflare Pages 部署）。负责用户操作面板、Builder 编辑器和账户管理。
2
Backend (写操作引擎) 运行在 VPS 上的 Node.js 服务。持有 DB、R2、KV 的最高写入特权。
3
Worker (分发网关) 拦截 *.885201314.xyz 域名的边缘微服务。像个“小保安”一样，只负责查 KV 路由并从 R2 取货返给访客。
4
Templates (资产库) 独立的 HTML/CSS 模板仓库。由 CI/CD 自动同步至 R2 的 /templates 目录。
5
Database & Auth (账房) 利用 Supabase (Postgres) 进行权限鉴定和原始配置数据的长久化存储。
6
Docs (知识库) 就是你现在看到的这套手册，负责记录项目的所有技术细节。
⚠️ 安全红线：
Frontend 和 Worker 严禁直接连接 Supabase 数据库！所有敏感数据的读取与修改必须通过 Backend VPS 代理进行，以防泄露机密密钥。
