🧑‍💻 模板开发与上传指南

作为一个前端切图仔/工程师，恭喜你找到了最舒服的模板开发方式：你只需要写纯正的 HTML、CSS和JS 文件，不需要懂任何构建工具或复杂的框架。

一、 一个模板的标准姿势

在本地电脑的 romancespace/templates/ 目录下，每一个文件夹就是一个模板项目。比如我们建一个名为 my_card 的模板，它的里面只能（且必须）有以下核心文件：

romancespace/templates/my_card/
├── index.html (必填) 网页骨架和占位符
├── schema.json (可选) 定义有哪几个空给用户填
├── style.css (可选) 你的样式表
├── script.js (可选) 你的动画或交互脚本
└── img/
    └── bg.jpg (可选) 图片素材，你想放多深都可以

二、 编写 index.html (注入灵魂)

这就是一张普通的网页，你只需要在想要展示“用户填写的文字”的地方，放上 {{参数名}} 即可。

<!DOCTYPE html>
<html>
<head>
  <!-- 引用本模板内部的 CSS，注意路径格式：/assets/你的模板名/文件名 -->
  <link rel="stylesheet" href="/assets/my_card/style.css">
</head>
<body>

  <h1>{{title}}</h1>
  <p>这是由 {{author}} 给你留的一段话。</p>

  <!-- 此处也可以引用模板内置图片 -->
  <img src="/assets/my_card/img/bg.jpg">

</body>
</html>
安全科普 (XSS 防御)：
不管用户在主平台里乱填什么恶作剧代码试图黑你的网页（比如填 <script>alert(1)</script>），系统在生成这页 HTML 之前，都会强制把敏感符号转义掉。所以，前端放心把 {{}} 贴在页面任何地方，绝对安全可用。

三、 编写 schema.json (配置字典)

🔄 定制化参数是怎么通信的？（必看映射关系）：

这三者是一一对应的齿轮：[主站传的 Data] -> [Schema.json 的 key] -> [HTML 的占位符]

1. 起点 (主站发起)： 主站服务器调用 API 接口时，传入了自定义数据。比如 "data": { "title": "老婆生日快乐" }。
2. 桥梁 (schema.json 定义)： 系统拿到数据后，会核对当前模板的 schema.json。只要里面定义过 {"key": "title"}，系统就会放行，提取出对应的这句“老婆生日快乐”。
3. 终点 (index.html 替换)： 最后，系统像做文本查找替换一样，把 index.html 源码里所有的 {{title}} 全部擦除，印上“老婆生日快乐”。

💡 如果主站 API 没有传 title 这个字段过来，或者用户留空了，系统就会智能降级，抽取 schema.json 里事先写好的 default 默认词填进去。

如果你上面的 HTML 里写了 {{title}} 和 {{author}}，主站如果需要生成“模板填写表单”，该以什么规范传参数？这里就是 schema.json 登场的地方。 

{
  "static": false,
  "fields": [
    { 
      "key": "title", 
      "type": "string", 
      "default": "默认大标题" 
    },
    { 
      "key": "paragraphs",
      "type": "array",
      "join": "</p><p>",
      "wrapStart": "<p>",
      "wrapEnd": "</p>",
      "default": ["这是第一段", "这是第二段"]
    }
  ]
}

schema.json 字段规范说明

  • static (Boolean): 当前模板是否为纯静态页面。如果设为 true，代表这个页面不接收任何用户的数据定制，系统处理此模板速度极快。
  • fields (Array): 这个模板里面所有可被修改的 {{参数}} 集合。

单个 field (字段) 可以配置什么：

属性 类型 必选？ 说明
key String 必填 HTML 中 {{}} 里的英文代号。
type String 必填 string (纯文本) 或 array (数组，常用于多段落或循环名册)
default Any 可选 用户如果传了空值，网页上默认显示的占位文字。
join String 特殊 仅当 type="array" 时有效，数组元素之间的拼接符号。例如表白段落的 </p><p>。
wrapStart / wrapEnd String 特殊 仅当 type="array" 时有效，在整个拼接好的字符串最外层包上一层。例如 <p> 和 </p>。

四、 上传部署到线上

自系统重构后，所有的模板现在统一存放在专属的 RomanceSpace-Templates 仓库中。上传模板最推荐、最稳妥的方式是直接利用 GitHub 的自动化流水线（CI/CD）。

方式 1：通过 GitHub Actions 自动部署（强烈推荐）

只要你的 RomanceSpace-Templates 仓库已经在 GitHub 上配置好了 RS_ADMIN_KEY 密钥，你只需要正常提交代码：

# 1. 提交你新写好的、或修改过的模板文件夹
git add src/my_card/
git commit -m "feat: add my_card template"

# 2. 推送到 Github
git push

就是这么简单！GitHub Actions 会自动检测你改动了哪个模板，并直接调 API 帮你上传到 Cloudflare 处理好一切。

方式 2：本地命令行上传（仅供本地极客调试用）

如果你在本地开发，想立刻强行塞进云端看效果，也可以呼叫仓库里自带的上传脚本：

# 第1步：切入 Templates 仓库根目录
cd C:\Users\xxx\...\RomanceSpace-Templates

# 第2步：在根目录建一个 .env 文件，写上密钥
# 编辑 .env 文件写入：RS_ADMIN_KEY="你的超强密钥"

# 第3步：执行上传！语法为 npm run upload 模板名 本地路径
npm run upload my_card ./src/my_card

五、 如果我想更新已有的模板怎么办？

比如你修复了 my_card 里 style.css 的一个样式 bug。你只需要：

像平时一样 git push 更新的代码即可。

系统极其聪明，当它发现你是覆盖更新时，它不仅会悄悄换掉静态资源文件，还会在后台把之前所有用过这个模板的几百个用户个人的专属旧网页，一口气顺带连锅端掉、全帮你重新生成一次新版的静态文件存入仓库。

整个过程极其平滑，哪怕此时正好有几万访客在看旧页面，他们所看到的依然是旧版快照，等几秒钟后刷新，就会无缝切到你的新版，中间绝对不会出现任何打断或 404。
