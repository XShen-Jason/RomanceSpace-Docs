Chapter 4

仓库生态：团队开发与协作流转

RomanceSpace 的代码高度模块化，分布在 6 个核心仓库中。为了确保开发效率与系统安全，我们需要遵循统一的协作流程。

1. 仓库图谱与角色

协作首要原则是：职责清晰，环境隔离。

仓库名称 核心职能 开发者关注点
RS-Frontend React 应用，UI 交互。 Vite 构建、移动端适配、AJAX 接口调用。
RS-Backend Node.js API，写操作中心。 R2/KV 操作逻辑、数据库 Schema、高并发限流。
RS-Worker 边缘路由，只读分发。 Wrangler 部署、子域名正则校验、缓存策略。
RS-Templates 纯净 HTML/CSS 蓝图。 设计审美、注入占位符 {{ id }} 的规范性。
RS-Docs 开发者手册。 本文档的维护，HTML 静态页面更新。

2. 自动化部署 (CI/CD) 流程

所有的部署都应通过 GitHub Actions 自动化进行，严禁私自绕过流水线。

典型发布路径：

1
提交代码 (Push)：开发者向 Master 分支提交代码。
2
触发 CI (Build)：GitHub Actions 启动。前端执行 npm build，后端检查 Linter。
3
自动分发 (Deploy)：
  • Frontend 自动推至 Cloudflare Pages。
  • Worker 自动推至 Cloudflare Edge。
  • Templates 自动推至 R2 云目录。

3. 本地开发环境建议

为了模拟真实的“上帝视角”，本地开发建议：

  • 后端：本地运行 npm run dev (3000端口)，配置 .env 指向 Supabase 的本地或开发库。
  • 前端：使用 Vite 的 proxy 功能，将 /api 代理到 3000 端口，解决跨域问题。
  • Worker：使用 npx wrangler dev 进行本地边缘环境测试。
