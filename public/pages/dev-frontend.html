🎨 Frontend 前端界面开发手册

做为五大仓库的一员，RomanceSpace-Frontend 是一个纯粹的 UI 视图层 (Single Page Application)。它没有任何状态留存和复杂的打包生成机制，所有业务逻辑全部通过调用 Backend API 完成。我们的核心法则是：核心逻辑绝不留在前端！

💡 核心配置绑定 (.env)：
前端由于缺乏任何处理私密数据（如 KV 或 R2 的 Key）的权限，因此它的 .env 只有一条：
VITE_API_BASE_URL=https://api.885201314.xyz/api，它唯一的任务就是呼叫这个远端计算大哥。

一、核心组件与信息交互流程流向

在这个单页应用中，分为两块主要的功能页面（组件），其流向如下：

1. 画廊层展示逻辑 (Gallery.jsx)

1
步骤 1：同步模板素材
举例：页面开启加载 `useEffect` 时，呼叫核心网关 GET /api/template/list。
2
步骤 2：直观卡片成型
举例：Backend 返回数组字典，前端遍历这些 JSON 画出精美的选项给访客选择其喜爱的排版类型。

2. 制作表单递交流程 (Builder.jsx)

3
步骤 3：收集信息与状态聚合
举例：小红进入到指定的 templateType 表单后，利用 useState 绑定了自己与男友的名称：boyName / girlName。
4
步骤 4：核心触发与渲染请求
举例：当点击提交时，页面会被 Loading 锁定不允许连点。随后调用核心方法 renderProject()，开始向远端的 Backend 排队发送数据。最终当对方回复 200 HTTP 并且发送了网页的新版连接才算完成一次重度交互。

二、唯一的网关通信处 (api/client.js)

为了可维护性，所有需要和 Backend 说话的代码，全部封装在这个文件里。严禁在单独的 React 组件中调用 fetch：

// 核心开通函数：向 Backend 发送熔铸请求的样板
export const renderProject = async (data) => {
    /*
      预期 data 结构:
      {
        subdomain: 'xiaoming',
        templateType: 'commemoration',
        data: {
            boyName: 'Jack',
            girlName: 'Rose'
        }
      }
    */
    const response = await fetch(`${import.meta.env.VITE_API_BASE_URL}/api/project/render`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data)
    });
    return response.json(); 
};
