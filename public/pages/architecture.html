🚀 核心概念与工作原理 (基于 CQRS 读写分离)

这是一个极度优化的高并发小网页分发平台（RomanceSpace）。为了能在近乎“免费”的前提下支撑极高的访问量，系统底层经过了 CQRS（命令查询职责分离）深度设计。

💡 重要提示：打开网址相当于访问 Worker！
用户的每一次访问（例如打开 love.885201314.xyz），流量第一时间都会打到 Cloudflare Worker 上，由网关决定是从缓存、还是 R2 返回最终页面。

一、 五大核心组件与配置速查

整个系统由 5 个核心仓库组装而成，职责清晰，绝不耦合：

1. 模板资产仓 独立资源库

核心配置： 模板内部的 schema.json，负责定义要给用户展示哪些输入框。

通俗比喻： 专门存放“未署名贺卡”的仓库，随时准备被拿去加工。

2. VPS 后端 核心中央流水线

核心配置： 根目录的 .env 文件，存放数据库密钥 (SUPABASE_SERVICE_ROLE_KEY) 与 R2 访问权。

通俗比喻： 公司的核心工厂。接收创建请求，将半成品模板和用户数据拼接成最终的静态 HTML。

3. CF Worker 全球分发门卫

核心配置： wrangler.toml，用于绑定 KV 与 R2 存储桶以便拥有读取权。

通俗比喻： 遍布全球的前台接待员，只负责拦截请求并“去仓库拿写好的 HTML 网页”。

4. KV & R2 资源存放 登记处与大仓库

核心配置： 都在 Cloudflare 控制台直接分配的命名空间与存储桶。

通俗比喻： KV 是一本小本子。里面只写谁开通了网页；R2 则是放静态 HTML 文件的大型免费仓库。

5. 前端 UI 仓 业务入口

核心配置： .env 文件里的 VITE_API_BASE_URL 指向后端 API。

通俗比喻： 放在门外的填写表单系统，与纯呈现文档网站一起构成了系统的外貌。

二、 核心工作流程（图解与示例）

我们将整个系统拆解为三个步骤，完美展现 CQRS 的 写算力集中化 和 读算力边缘化：

1
第一步：开发者上传模板
举例：开发者小李把名为 flower_theme 的模板推送到了 Git，系统将其同步至 R2 成为公用资产。
2
第二步：主平台开通专属页面 (强写链路)
举例：小明在前端填上“我爱你”，后端接收后，经过复杂字符串拼接生成 xiaoming.html 并推送到 R2 仓库保存。同时在 KV 写下：xiaoming 已激活。 
// 这是一个简易的核心数据结构样例
const submitData = {
  template: "flower_theme",
  data: { lover: "小红", text: "我爱你" }
};
3
第三步：访客高速阅读 (极速读链路)
举例：几万人打开 xiaoming.885201314.xyz 时，流量直达 Worker。Worker 查 KV 确认有小明后，转身去 R2 拿出 xiaoming.html，交给缓存并在之后 1 小时内直接用缓存扛并发。

三、 总结

CQRS 把读和写完全拆解：

  • 写（Write）由于并发量低、计算复杂，交由独立自主的 Node.js VPS 后端稳扎稳打。
  • 读（Read）由于并发量极高、计算几乎没有，交由 Cloudflare Worker 从 R2 提取缓存给全世界。
