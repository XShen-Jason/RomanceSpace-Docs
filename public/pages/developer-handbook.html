📖 RomanceSpace 开发者入门手册 (Developer Notes)

欢迎来到 RomanceSpace 项目！这套系统看似有很多仓库，但本质上都是由**“一个核心思想”**串联起来的。 这份文档将以最通俗的语言，带你理清整个架构的流转逻辑、各个仓库的分工，以及如何进行日常开发。

🌟 第一回：核心架构思想 —— 为什么我们要搞这么复杂？

痛点与目标

如果你只做个单体应用（比如传统的 PHP/Java 网站），一旦用户多起来，服务器瞬间就会卡死，或者你的钱包会被云服务商掏空。 我们的目标是：“让 2h2g 这种最廉价的服务器，支撑起百万级甚至是千万级的并发访问！”

解决方案：CQRS（读写分离）+ 边缘存储

这个高大上的词，在 RomanceSpace 里的白话就是：

“生成网页的时候慢慢来（VPS 服务器），看网页的时候直接从最近的 CDN (Cloudflare) 拿！”

系统中存在两波人：

  1. 创作者 (小红)：她来到我们的平台 (Frontend)，写情话，挑模板，点击“生成”。
    • 这个操作是**“写操作”**，它很重。这部分流量会导向我们自己的 VPS (Backend)。VPS 老黄牛会慢条斯理地把她的文字塞进模板里，变成一段纯净的 HTML 代码，然后塞进云仓库 (R2)。
  2. 吃瓜群众 (上万个网友)：小红把链接发到朋友圈，上万人同时点开网址。
    • 这时，访问请求根本到不了 VPS！全都在半路的 Cloudflare Worker (边缘网关) 被拦截了。Worker 直接从云仓库 (R2) 里拿出写好的 HTML 返回。这就叫**“读操作”**。

🏢 第二回：四大山头（Repository）的职责划分

为了互不干扰，我们将代码拆成了四部分：

1. 🎨 RomanceSpace-Templates (模板素材库)

身份：装潢队的样板间。 内容：纯静态的 HTML/CSS/JS 文件（如纪念日、表白墙等风格）。 重点：这里面有个 schema.json（Manifest），它是向前端收银台汇报的：“我这个模板需要用户填『标题』、『日期』和『留言』三个框”。

2. 🖥️ RomanceSpace-Frontend (用户收银台 & 编辑器)

身份：大堂接待员（纯前端 SPA，React 等构建）。 功能：用户在这里登录、选模板、填表单。 核心机制 (BSR)：当用户在编辑内容时，前端会把基础的 HTML 拉过来，在浏览器本地（利用 Iframe）进行文字替换，实现毫秒级无服务器消耗的实时预览。

3. ⚙️ RomanceSpace-Backend (后台中央厨房)

身份：主厨与大掌柜 (Node.js VPS)。 功能：

  • 唯一拥有数据库和 R2 读写权限的地方。
  • 接收前端传来的数据，真正生成最终的静态网页（存入 R2）。
  • 安全防线 (黑名单)：内置了 DNS 域名黑名单系统，防止用户把系统保留字（如 api, www）注册成了自己的情话页面。

4. 🛜 RomanceSpace-Worker (全球快递员)

身份：Cloudflare 边缘路由器。 功能：

  • 任何外界访问 *.885201314.xyz 的流量，第一个撞上的就是它。
  • 如果请求 api.，它就转发给 VPS；如果是 assets.，它就去读取静态资源并加上长达 7 天的死缓存。
  • 如果请求的是普通用户域名（如 anna.），它就去 R2 取出 pages/anna/index.html 送给用户。

🌊 第三回：数据是怎么跑的？(流量大揭秘)

场景 A：小红创建了一个专属页面

  1. Frontend：小红填好表，选好域名 anna，点击“生成”。
  2. Backend:
    • 收到请求，检查 anna 有没有在黑名单里？（通过内存缓存判断，不花一分钱额度）。
    • 检查通过！把小红的内容塞进“表白”模板的 HTML 里。
    • 把 index.html 扔进 R2 云仓库的 pages/anna/index.html 位置。
    • 告诉 Cloudflare：“这是小红刚建好的，别给我放旧的缓存！”
  3. Frontend：告诉小红：创建成功，跳转 anna.885201314.xyz/?preview=当前时间戳 强制看一眼最新版。

场景 B：小明看到朋友圈的链接点进去

  1. Worker (快递员)：接到 anna. 的快递单号。
  2. Worker 去 R2 云仓库找包裹 pages/anna/index.html。
  3. Worker 告诉下一站的 CDN 节点：“这个包裹在这个小时内谁还要，就直接在这个镇子上发给他，别再来问我了！”（Cache-Control: max-age=3600）。
  4. 所以如果一万个人同时点开，只有第一个人让 Worker 跑了一趟，剩下 9999 个人全是白嫖 CDN 的缓存，速度飞快，成本为零！

🛠️ 第四回：开发者如何优雅地开发？(实战篇)

我是新来的，我要怎么在这个架构下调试代码？

步骤 1: 环境准备

  • 确保电脑装了 Node.js。
  • 克隆四个仓库（放到同一个父文件夹下，就像现在的结构）。

步骤 2: 跑起后端 (VPS 模拟)

进入 RomanceSpace-Backend：

npm install
# 配置好你的 .env 文件，需要包含 Supabase 和 R2 的密钥
npm run dev

此时你的大掌柜在 localhost:3000 醒了。

步骤 3: 跑起前端 (大堂接待)

进入 RomanceSpace-Frontend：

npm install
npm run dev

大堂接待员在 localhost:5173 开始营业。你可以随意点击，因为网络请求会发给 localhost:3000。

步骤 4: 跑起 Worker (快递员模拟)

进入 RomanceSpace-Worker：

npm install
npx wrangler dev

在本地，Wrangler 会完美模拟 Cloudflare 的环境，拦截你的请求并代理到对应的路径。

🚨 第五回：系统安全与运维锦囊

1. 我想保留一个域名（比如 admin.885201314.xyz），不想被用户抢注怎么办？

非常简单，甚至不需要动代码重启服务器！

  • 登录 Cloudflare 后台，找到 KV 存储 ROMANCESPACE_KV。
  • 添加/修改一个键值对，键为 __sys__blocklist，值填入 JSON：["admin", "love", "root"]。
  • 接着，用 Postman 调一下你后端的雷达接口：POST https://api.xxx.com/api/project/config/refresh-blocklist
  • VPS 掌柜就会立刻下发通知：这几个名字从现在起禁售！

2. 为什么在 DNS 里加了解析，页面还是 404？

记住老规矩：

  • 如果是外部独立部署的项目 (如另一个 CF Pages)：只要加到黑名单保护起来就行，系统底层（CF Pages 路由优先机制）会直接把流量劫走。
  • 如果是本库内的新逻辑：那除了配 DNS，还要去 RomanceSpace-Worker 里面的 index.js，加上一句 if (host === '新名字') { 你的处理逻辑 }，否则 Worker 这个保安就不认识它，会按照老规矩报错。

当你读完这篇指南，无论你看到哪个仓库的代码，只要牢记：VPS 负责脏活累活和写，Worker 负责分发和拦缓存，你就已经是一个成熟的 RomanceSpace 架构师了。
