🔗 子域名分配与数据绑定流程

这个体系最魔法的地方在于：只要主平台发一纸“调令”（调一条 API），属于用户专属的小网页就立刻在几秒内诞生，并分配好了独一无二的子网址（如 xiaoming.885201314.xyz）。

本文说明这条链路是怎么走通的。

一、基础原理：Cloudflare DNS 泛解析

为了做到让每个用户都能自由命名网址，而不需要管理员去后台一条一条添加 DNS 记录，我们在域名管理处设置了 泛解析（Wildcard DNS）。

配置内容： *.885201314.xyz -> 指向 Worker

  • 也就是说，无论是 apple.885201314.xyz 还是 banana.885201314.xyz，DNS 解析后都会被瞬间转发到我们的 RomanceSpace Worker 门前。
  • 到了门前后，Worker 会掐头去尾，提取出最前面的那个词（比如 apple 或 banana）。
  • Worker 拿着这个词，去 KV（指示牌）里翻找：这个词有被注册开通过吗？

二、业务运转全流程：从填表到网页诞生

下面展示了一个完整的“开通”链路。这是主站服务器（即处理用户付费、表单提交的那台机器）和 Cloudflare Worker（边缘节点）直接打交道的过程。

1

用户在您的“主网站”浏览

小明在您的主站页面上逛，看中了一个纪念日模板（代号：anniversary）。

2

用户填写定制信息

小明选定后，主站网页弹出一个表单，让小明输入：男方名字、女方名字、想说的话、想要的前缀拼音。小明填入了 xiaoming。

3

主站服务器查重与校验

主网站的 PHP/Java/Node 服务器接收到了提交。由于 xiaoming 这个词全站唯一，主服务器查了下自己的数据库，发现没人用过，于是允许创建（也许还收了小明 9.9 元）。

4

【核心】主站调用 Worker API 发送调令

主服务器整理好小明填的数据，往 Worker 的接口（POST /admin/render-page）发了一道命令请求。

POST https://romancespace.885201314.xyz/admin/render-page
Header: X-Admin-Key="你的安全密钥"
Body: {
  "subdomain": "xiaoming",
  "type": "anniversary",
  "data": { "names": ["小明", "真真"], "message": "一生一世" }
}
5

Worker 收到调令，后台秒级预渲染

Worker 拿到请求后做两件事：
1. 像印刷机一样，把“小明”和“真真”等数据，当场印到 anniversary 的原始 HTML 页面里。
2. 把印好的这份 HTML 网页丢进 R2 大仓库里，并清空旧的缓存。

6

访问生效

Worker 给主服务器返回 {"success": true}。主服务器随即在页面上告诉小明：“您的专属网页已建好！”
小明此时点开 https://xiaoming.885201314.xyz，秒开网页，数据已然是他定制的内容。

三、关于数据修改与更新

如果小明第二天决定改掉那句“一生一世”怎么办？

完全不用担心。主站只需要重做一遍上面的步骤 4（把新数据再次 POST 给 Worker），Worker 就会重新渲染一张带有新文字的网页，并覆盖掉 R2 仓库里的旧网页，同时一脚把大门口旧的 Cache 踢飞。

小明刷新网址，新文字立马出现。
