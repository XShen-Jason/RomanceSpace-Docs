🗺️ 项目总览 — 五大核心仓库协作机制

本文档是所有技术成员加入 RomanceSpace 的第一站。平台基于极致的微仓库解耦思维（CQRS读写分离），将整个平台拆解成五个职责绝对专注的代码库。

一、系统的起点：打开网址等价于访问 Worker

💡 核心概念说明：由于我们将复杂的网页提前烘焙固化在了服务器中缓存，所以 打开生成的个人网页（如 `xxx.885201314.xyz`），其实相当于请求直接访问了你的 Worker 网关！
1
第一步：网关解析接入请求
举例：当全网几十万群众同时在浏览器中敲下并回车 https://love.885201314.xyz，泛域名 DNS 自动将请求拦截并转交给 RomanceSpace-Worker。
↓
2
第二步：路由侦测与直读反馈
举例：Worker 不处理任何花里胡哨的代码，直接询问 KV：“love 前缀有绑定页面吗？”得知后立马去后勤（R2 存储器）搬走静态 HTML 返回给 love.885201314.xyz 给观众看，这便实现了极限的高并发防御。

二、五大核心仓库速查与核心配置（职责流转机制）

通过组合下面的五个仓库，系统完成了一条：“发布->解析->写入->边缘分发”的完整闭环。

📦 模板资产仓 - RomanceSpace-Templates

【核心职责】

✓
步骤记录：切图工程师编写纯HTML、CSS，并在上传。它没有复杂的运行环境，完全与主系统解耦。独立被 GitHub 的 CICD 控制流上传到平台。
举例：开发者小红新建 flower_theme 并加入动画样式，通过 git push 后被纳入平台模板库中。

【核心配置举例】在模板内的 schema.json 声明核心的数据槽：

{
  "static": false,
  "fields": [
    { "key": "lover_name", "type": "string", "default": "宝贝" }
  ]
}
🎨 前端 UI 仓 - RomanceSpace-Frontend

【核心职责】

✓
步骤呈现：基于 Vite React 的管理系统，供大盘使用者进行挑选模板与写入文字。仅仅进行只读页面的展示并呼叫后端 API。
举例：表白者进入主页，在输入框填写了 lover_name 为“小红”，点击提交后前端使用 fetch 将指令推发给后台。

【核心配置举例】根路径的 .env 文件存放请求的统一域前缀：

# 指向 VPS 服务的后端入口点
VITE_API_BASE_URL=https://api.885201314.xyz/api
⚙️ 后端承重仓 - RomanceSpace-Backend

【核心职责】

✓
步骤融铸：作为唯一的掌控大权的“写入引擎”，它将前端收集到的参数、存储的模板融合成具体的 HTML 文件。并将生成的 HTML 覆盖进 R2 并记录。
举例：VPS 后台获取到刚才的请求，拼凑成带名字的 HTML，调用 SDK 执行存储动作（保存到 project_{id}.html）。

【核心配置举例】系统特权核心变量全部挂载至 .env 文件，绝不可外泄：

# 超高权 Database Token
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=ey... 

# Cloudflare 管理权调用密钥
R2_ACCESS_KEY_ID=xxx
R2_SECRET_ACCESS_KEY=xxx
CF_ACCOUNT_ID=xxx
🌐 边缘网关仓 - RomanceSpace-Worker

【核心职责】

✓
步骤宣发：作为整个微服务流水线的最后一端。正如“一”中所述，它是打开网站时直面全网络访客的读取缓冲大坝。没有写权限，仅对 CDN 进行路由指派与资源派发。
举例：小红的好友们通过连接查看网页时，均不麻烦后端服务器操作。Worker 会从 CDN 或底层 R2 读取文件缓存 1 小时后给访客展示。

【核心配置举例】通过 wrangler.toml 绑定并授权外部 Cloudflare 内线资源的调用接口：

name = "romancespace-worker"
main = "src/index.js"

# 绑定系统路由 KV 
kv_namespaces = [
  { binding = "ROMANCESPACE_KV", id = "xxx" }
]

# 允许从指定水桶读取生成的 HTML 模块
[[r2_buckets]]
binding = "ROMANCESPACE_R2"
bucket_name = "romancespace-pages"

【核心职责】

三、核心 API 工作机制与业务调用

为了使上述 5 大模块产生联动，通常使用 REST API 在前端至后端传递重要指令。这里列举系统内核心的生成网站 API进行释义：

1
请求构建阶段 (Request)
举例：当所有的参数组装完毕后，前端采用 POST 途径向后端发送以下结构的 JSON 数据报文进行核心渲染呼叫： 
// 前端调用的接口地址
const ENDPOINT = "https://api.885201314.xyz/api/project/render";

// 发送的配置数据体，您可以点击复制该测试样例！
const payload = {
  "templateId": "my_card",     // 需要采用的模板
  "domain": "love",            // 要求的二级访问子域名前缀
  "data": {                    // 对应该模板 Schema 的真实数据
    "lover_name": "小红",
    "paragraphs": ["我爱你", "长长久久"]
  }
};

fetch(ENDPOINT, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload)
});
2
后台执行并反馈 (Response)
举例：后端经过数秒的渲染和分发后，返回代表操作闭环成功的数据结构。并赋予该网站实时去缓存的强制查看（预览）权： 
{
  "success": true,
  "message": "静态部署成功并刷新边缘服务器！",
  "data": {
     "previewUrl": "https://love.885201314.xyz?preview=1710000000"
  }
}
