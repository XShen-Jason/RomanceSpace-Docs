⚙️ Backend 服务端开发手册 (写算力核心)

RomanceSpace-Backend 是运行在独立 VPS 上的 Node.js (Express) 进程。在 CQRS 架构中，它是绝对权威的“控制平面”与“写入引擎”。

一、为什么不放在 Cloudflare Worker？

传统的 Serverless (如 Worker) 对 CPU 毫秒级限制极度严苛。模板的渲染（把几千行 HTML 取出来、执行正则扫描替换、最后重新塞回大型对象存储）是一个极其昂贵的 I/O 和 CPU 操作。如果放在 Worker，高并发下会导致大规模请求超时死锁。

因此，Backend (VPS 后端) 包揽了这件重度脑力活，将组装好的死块直接推走。

二、核心文件目录

src/
├── app.js               // Express 实例入口、跨域层
├── routes/              
│   ├── project.js       // 用户开通网页核心 API
│   └── template.js      // 模板上传与列出 API
├── utils/
│   ├── cf.js            // Cloudflare API(R2/KV/Cache) 打交道的底层库
│   ├── html.js          // HTML 字符串注入工具 (最繁重的渲染引擎)
│   └── supabase.js      // 数据库持久化连接

三、核心源码流程：POST /api/project/render

这是整个平台被调用最频繁、最重要的接口。当前端呼叫此接口时，Backend 开始它的工作：

  1. 鉴权与限流： 检查基础权限和限流墙（防 DDOS）。
  2. 拉取母板： 根据传入的 templateType 参数，通过 cf.js 从 R2 提取出原汁原味的、带有 {{双大括号}} 的原始 index.html 和 schema.json。
  3. 极速熔铸 (html.js)：
    • 遍历前端传来的 data，利用正则在 index.html 字符串中进行精准锚点替换（String Replace）。
    • 执行基础的安全转义，防止前端发来的字符串包含 XSS 恶意脚本。
  4. 推入仓库 (Push to R2)： 生成专属此人的一张新的 HTML (如 pages/xiaoming.html)，通过 R2 REST API 硬写入对象存储。
  5. 路由挂载 (Push to KV)： 为了让 Worker 认识小明，后端向 Cloudflare KV 写入键值对 {'xiaoming': '...' }，相当于挂号登记。
  6. 持久化沉淀 (Supabase)： 防止 R2 数据丢失，将这一条购买和开通记录（包含填写的 raw JSON 参数）通过 supabase.js 用 jsonb 格式永久落库。
  7. 缓存失效 (Purge Cache)： 这是一个老客户的“更新”操作时，调用 CF Cache API 将全球所有边缘节点的 xiaoming.885201314.xyz 瞬间清理，强制下次拉新。

四、工具底层 (utils/cf.js)

后端之所以能控制全球的 Cloudflare 节点，是因为它握有超级权力（CF_API_TOKEN 等配置）。


// utils/cf.js 伪代码示例
export const putToR2 = async (key, buffer) => {
    // 采用 AWS S3 SDK 规范来连接 Cloudflare R2
    const client = new S3Client({
        region: 'auto',
        endpoint: process.env.R2_ENDPOINT,
        credentials: { ... }
    });
    // 硬性并发推送
    await client.send(new PutObjectCommand({ Bucket, Key: key, Body: buffer }));
}
⚠️ 绝对隔离： Frontend 乃至主站，绝对不允许直接接触这些包含 R2 Key, KV ID 的代码。一切强写入行为只能通过 Backend 提供的 HTTPS REST API 执行。
