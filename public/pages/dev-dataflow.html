📊 平台全局数据流转分析 (Data Flow)

这个章节将从全栈的角度，以上帝视角解剖一个名为 "xiaoming" 的表单是如何贯穿 Frontend -> Backend -> R2/KV -> Worker -> 物理浏览器的。

一、 数据的起跑（Frontend -> JSON）

📍 React Builder.jsx

用户选择了名为 classic_love 的模板。提交了如下原生对象状态：


{
  "subdomain": "xiaoming",
  "templateType": "classic_love",
  "data": {
    "me": "小明",
    "you": "小红",
    "startDate": "2024-01-01"
  }
}
⬇ 跨海传输 (HTTPS POST /api/project/render)

二、 数据的熔铸（Backend -> HTML注入）

📍 Express /routes/project.js

Node.js 通过提取模板，获得了 R2 里的 index.html 字符串：


<h1>{{me}} 爱 {{you}}</h1>
<p>我们在一起相爱了 {{_calcDays(startDate)}} 天</p>

Backend 的内部算法引擎高速正则替换，生成了最终字符串结果：


<h1>小明 爱 小红</h1>
<p>我们在一起相爱了 99 天</p>
⬇ 资产沉淀 (S3 API & REST API)

三、 数据的封印（R2 & KV & Supabase）

📍 数据库持久层写入

  • 【R2 对象存储】生成 /pages/xiaoming.html，它的内容就是上面组装好的“死块”HTML。
  • 【KV 键值系统】存入键 "xiaoming"，值为 {"template":"classic_love", "version":1}。这是为了以后读取时的快照检查。
  • 【Supabase 数据库】在 PostgreSQL 表 projects 增加一行记录，原始 JSON 原封不动沉底，方便以后“后台二次编辑”能把数据反选出来。
⬇ 数千万人访问 (DNS Wildcard)

四、 数据的喷发（Worker -> Cache -> 浏览器）

📍 Cloudflare Edge 读取流

用户访问 https://xiaoming.885201314.xyz：

  1. Cloudflare CDN (一级缓存) 完全失效或未设置。
  2. Worker 脚本文本激活，看到 Request 请求中 Hostname 是 xiaoming。
  3. 它立即 await KV.get('xiaoming')。获得配置（鉴权通过）。
  4. 前往 R2 拿到早就渲染好的、一锤定音的 HTML，加上 Cache-Control: public, max-age=3600，并注入拉新尾部链接。
  5. 直接抛回给浏览器客户端，同时让全地球这个节点的 CF 代理商将这段响应内存挂起（1 小时内有效）。
