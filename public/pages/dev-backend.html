⚙️ Backend 服务端开发手册 (写算力核心)

做为五大仓库的核心，RomanceSpace-Backend 是运行在独立 VPS 上的 Node.js (Express) 进程。在 CQRS 架构中，它是绝对权威的“控制平面”与“写入引擎”。

💡 核心机制与配置 (.env 文件)：
传统架构容易触发 Worker I/O 和 CPU 死锁限制。Backend 通过提取 R2 文件进行正则替换，这属于重度计算操作。因此，后端的 .env 文件中配置了特权 SUPABASE_SERVICE_ROLE_KEY 数据库密钥和 R2 云凭据，一切高权限操作都在此收口。

一、核心源码流转步骤

当接收到调用请求 POST /api/project/render 时，后台进行以下处理：

1
步骤 1：鉴权与提取模板
举例：检查防刷机制后，使用后台的特权访问 R2 仓库提取出未加工的 index.html 和 schema.json 骨架资源。
2
步骤 2：急速熔铸（计算渲染）
举例：利用正则匹配算法，安全地在 HTML 中注入“小明”和“小红”等自定义数据，生成纯静态字符串。
3
步骤 3：多方沉淀与清障
举例：将这个专属的 HTML 直接写入 R2。接着将域名加入 KV 路由字典。最终命令 Cloudflare 刷掉老旧的 CDN 缓存（Purge Cache），并把源数据归档到 Supabase。

二、核心工具底层示例

通过底层的 cf.js 进行 Cloudflare S3 兼容的高效推送：

// utils/cf.js 推送核心样例
export const putToR2 = async (key, buffer) => {
    // 采用 AWS S3 SDK 规范来连接 Cloudflare R2
    const client = new S3Client({
        region: 'auto',
        endpoint: process.env.R2_ENDPOINT,
        credentials: { 
            accessKeyId: process.env.R2_ACCESS_KEY_ID, 
            secretAccessKey: process.env.R2_SECRET_ACCESS_KEY 
        }
    });
    // 高并发状态下，以 buffer 流快速抛入仓库
    await client.send(new PutObjectCommand({ Bucket, Key: key, Body: buffer }));
}
⚠️ 绝对隔离： Frontend 乃至主站，绝对不允许直接接触这些核心凭证。所有的复杂计算、组装、推包都必须依赖 Backend API 执行。
