🎨 Frontend 前端界面开发手册

RomanceSpace-Frontend 是一个纯粹的 UI 层 (Single Page Application)。它没有任何状态留存，所有业务逻辑全部通过调用 Backend API 完成。我们的核心法则是：前端只负责渲染和收集表单。

一、目录解剖与核心挂载

前端基于 React (Vite) 搭建，移除了传统 SPA 的复杂状态管理（如 Redux），仅使用 React Hooks 进行组件内状态流转。

src/
├── api/
│   └── client.js        // 唯一与Backend通信的接口层
├── components/          // (可复用UI组件)
├── pages/               // 路由页面层
│   ├── Home.jsx         // 官网主页
│   ├── Gallery.jsx      // 模板画廊层 (GET API展示)
│   └── Builder.jsx      // 开通制作层 (POST API提交)
├── App.jsx              // 核心路由挂载
└── main.jsx             // React 根节点

二、核心组件与数据流

1. App.jsx (路由网关)

使用 react-router-dom 规范页面跳转，保证 URL 体验。

2. Gallery.jsx (模板画廊)

作用：呈现所有已上架的模板。它是用户的主入口。

  • 生命周期初始化时，调用 api/client.js 的 getTemplates()。
  • 底层发起 GET /api/template/list 请求到 Backend VPS。
  • Backend 返回可用模板的 JSON 数组（含 name、version、配置字段）。
  • 将 JSON 映射成一个个直观的卡片。

3. Builder.jsx (开通表单构建器) - 核心核心

作用：收集用户要开通的域名和动态参数（如姓名、相识天数），并呼叫 Backend 进行“熔铸”。

流程解析：

  1. 从 URL 或状态中接收上一步 Gallery 传来的模板 type (如 `commemoration`)。
  2. 利用 React useState 双向绑定表单：
    • subdomain: 用户想要的域名前缀。
    • formData: 一个深度对象，对应模板 schema 要求的所有自定义字段。
  3. 点击提交，触发 renderProject()，开始向 Backend 发送开通指令。在收到 200 SUCCESS 之前，处于 Loading 锁死状态。

三、api/client.js (网关代理)

所有需要和 Backend 说话的代码，全部封装在这个文件里。绝不允许在组件里直接 fetch。


// 核心开通函数：向 Backend 发送熔铸请求
export const renderProject = async (data) => {
    /*
      data 结构:
      {
        subdomain: 'xiaoming',
        templateType: 'commemoration',
        data: {
            boyName: 'Jack',
            girlName: 'Rose'
        }
      }
    */
    const response = await fetch(`${API_BASE_URL}/api/project/render`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data)
    });
    return response.json(); 
};
环境变量： 前端需要知道 Backend 的地址，因此需要在 .env 文件中配置 VITE_API_BASE_URL=https://api.885201314.xyz 才能正常运行。
