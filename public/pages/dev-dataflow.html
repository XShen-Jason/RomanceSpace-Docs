📊 全端交互与数据流转 (Data Flow 实战图)

这个章节将从全网的视角，解剖一个名为 "xiaoming" 的表单是如何在前后端之间进行交互，并贯穿整个基础设施 (KV/R2/Supabase/Worker) 的最终生成流程的。

一场完美的生命周期旅程

1
生成请求发射 (Frontend UI 介入)
动作：小明在 RomanceSpace-Frontend 用户端输入了自己与女友的参数信息，并点击“确认开通”。前端唯一的任务就是把数据组合，向 Backend 发起通信！ 
// 前端 Fetch 调用举例
const payload = {
  "subdomain": "xiaoming",
  "templateType": "classic_love",
  "data": { "me": "小明", "you": "小红" }
}
fetch('https://api.885201314.xyz/api/project/render', { method: 'POST', body: JSON.stringify(payload) })
⬇(通信：HTTPS POST 跨海抵达 Backend VPS 服务器)
2
算力中枢熔铸与多方入库 (Backend 处理)
动作：RomanceSpace-Backend 接收请求，成为绝对主力。
- 它首先从 R2 下载 classic_love 模板。
- 执行 CPU 密集型正则代码，将模板变为：<h1>小明 爱 小红</h1> 的死静态 HTML 字符串。
- 调用 R2 接口：将被组装好的 HTML 文件传入 R2 (存入 xiaoming.html)。
- 调用 KV 接口：写入 { "xiaoming": "true" } 的路由注册表。
- 调用 Supabase DB：用特权密钥，把小明填的原始表单存档在 Postgres 数据库中。 
// 后端调用不同云端基础设施的 Node 伪代码范例
await supabase.from('projects').insert({ id: 'xiaoming', raw_data: payload.data }); // 入库 Supabase
await cloudflareKV.put('xiaoming', 'true'); // 增加路由记录至 KV
await s3Client.send(new PutObjectCommand({ Bucket, Key: 'xiaoming.html', Body: generatedHtml })); // HTML 灌入 R2
res.json({ success: true, url: "https://xiaoming.885201314.xyz" }) // 响应回 Frontend
⬇(物理分享：用户把生成的网址 https://xiaoming.885201314.xyz 发给了微信好友)
3
极速网关拦截分配 (Worker CDN 响应)
动作：好友点开网址的一瞬间，直接撞上了 RomanceSpace-Worker 边缘网关。
- 网关秒搜 KV 数据字典：问：“有 xiaoming 这个人的路由吗？” KV 说：“有！”
- 网关掉头去 R2 存储器 捞出刚刚打出来的 xiaoming.html 文件。
- 将网页原封不动丢回好友的浏览器，并且向 Cloudflare Cache 缓存该页面长达 1 小时，下次别人点开直接 0ms 返回。 
// Worker 处理访客的边缘读取逻辑
const isValid = await env.ROMANCESPACE_KV.get('xiaoming'); // 读取 KV 
if (isValid) {
  const htmlFile = await env.ROMANCESPACE_R2.get('xiaoming.html'); // 读取 R2
  return new Response(htmlFile.body, { headers: { "Content-Type": "text/html", "Cache-Control": "max-age=3600" }});
}
